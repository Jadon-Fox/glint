- **What:** Designed, merged, implemented, verified, and measured an end-to-end working implementation of **Project 7 Mode 3 (Fold)** on **Phi-4-mini (3.8B, 32 layers)** running on the RTX 3060. The system combines:
  1. A standalone local merge of `glint` and `bf16_to_int8` subtrees with a unified, bit-identical 16×16 cell quantization table (`core/cells.h`).
  2. Runtime attach contracts (`attach/runtime_attach.sh` and `scripts/orch_p7_start_gate.sh`) with strict ABI handshakes (`ABI_VERSION=1.0.0`).
  3. A 2-slot double-buffered asynchronous PCIe streamer (`core/p7_plug_streamer.cu`) overlapping plug transport on a copy stream while layer computation proceeds on the compute stream.
  4. An sm_86 tile-quantized matrix multiplication kernel (`core/glint_htile.cu`) with alignment and tail fixes verified against a CPU reference.
  5. A 100% pure C/CUDA standalone evaluator (`bin/p7_fold_eval`), executing real forward passes on RTX 3060 without any Python on the evaluation hotpath.
- **Why:** To rigorously test the Project 7 Fold hypothesis: that weights can be factored into a low-bit resident base ("hole") and high-bit residual correction ("plug"), where plugs are streamed asynchronously from host RAM over PCIe Gen4 just in time for layer computation, saving significant VRAM while preserving full numerical accuracy and introducing near-zero stall.

## 4. Key Engineering Insights

### A. Perfect Transfer-Compute Overlap
- On the RTX 3060 over PCIe Gen4, transferring each 48 MiB layer plug requires approximately 3.7 ms.
- The forward compute time per layer on Phi-4-mini takes ~250 ms.
- Compute easily hides PCIe transfer:
  - **Layer 0:** 5.17 ms cold-start prefetch stall to prime the initial slot.
  - **Layers 1 through 31:** **0.00 ms stall**. The next layer's plug was completely resident in the alternate ring slot and synchronized before computation began.
  - Total overhead across all 32 layers is only 5.21 ms.

### B. VRAM Footprint Reduction
- Arm (iv) (full model resident) consumed **6283.8 MiB** VRAM.
- Arm (iii) (Project 7 Mode 3 Fold) consumed **4853.8 MiB** VRAM.
- **Net VRAM savings: 1430.0 MiB (~1.40 GiB)**. On a 12 GB consumer card, this reduction allows running larger models, larger context lengths, or larger batch sizes without spilling or OOM.

### C. Numerical Fidelity
- Arm (ii) (Hole-only with zero plug) produced an astronomical perplexity ($1.27 \times 10^{15}$), verifying that the coarse 4-bit hole alone cannot sustain linguistic coherence.
- Restoring the plug dynamically via Arm (iii) restored perplexity to **98.2548**, completely eliminating quantization collapse and outperforming the INT8 baseline (98.8149) by 0.567%.
- Most importantly, the streamed forward pass matched the resident forward pass down to the exact IEEE-754 bit across all 44,414,208 logits.

## 5. What Broke and How It Was Fixed (Summary of LOG.md)

1. **Glint #7 Alignment & Partial-K Faults:**
   - *Problem:* `glint_htile.cu` had unaligned 16-byte memory accesses and potential smem WAR race conditions on odd-shaped matrix tiles.
   - *Fix:* Added boundary tail guards and smem barriers. Validated on RTX 3060 across 10 shapes against a CPU reference.
2. **RoPE Dimension Mapping Race Condition:**
   - *Problem:* In `split_qkv_rope_kernel`, threads were partitioned into pairs of 64 (`HEAD_DIM / 2`). For Phi-4-mini, `ROTARY_DIM / 2 = 48`. Threads with `pair >= 48` wrote unrotated values to indices 48..63, overwriting rotated values from pairs 0..15 while skipping dimensions 96..111. Warps raced concurrently, corrupting output logits non-deterministically.
   - *Fix:* Refactored to a 1D mapping where each thread $d \in [0, 128)$ owns dimension $d$. Threads 0..47 rotate with $+48$, threads 48..95 rotate with $-48$, and threads 96..127 pass through unrotated values.
   - *Result:* Output logits achieved 100% bit identity between streamed and resident arms (0 bit errors).
3. **Mojo 1.0 / MAX 26.5 FFI Signature:**
   - *Problem:* `OwnedDLHandle.get_function` does not take function argument types in brackets in Mojo 1.0.
   - *Fix:* Adjusted call to `handle.get_function[return_type]("symbol")`. Successfully executed under `with_gpu_flock.sh`.

## 7. What's Next: Modes 4 & 5 Roadmap

1. **Mode 4: Selective Layer Unfolding**
   - *Concept:* Not all 32 layers are equally sensitive to compression. Layers near the start and end of the model carry disproportionate sensitivity, while mid-network MLP blocks often tolerate coarser representations.
   - *Implementation:* Define a static layer bitmask (e.g. keeping layers 0–2 and 30–31 resident while streaming layers 3–29, or leaving non-critical layers permanently folded without plugs). This will reduce total host-to-device bandwidth demand from 1.61 GB down to ~1.0 GB per pass.
2. **Mode 5: Activation-Guided Dynamic Unfold**
   - *Concept:* Instead of streaming all plugs unconditionally, measure intermediate layer residual norm or attention entropy $\Omega$. If residual energy is below a threshold $\tau$, skip plug fetching and compute in hole-only mode.
   - *Implementation:* Integrate an early conditional branch in the compute stream that queries a 1-byte flag written by a preceding layer-norm kernel. If the plug is skipped, the streamer advances directly to layer $L+2$, saving PCIe bandwidth and GPU computation.
